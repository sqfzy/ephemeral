## 讨论全文

### 核心发现

当前打点架构：
- Socket: recv() 返回后 TSC::now()，加 SO_TIMESTAMPING 提供的 kernel_rx_delay_ns 补偿
- DPDK: rte_eth_rx_burst() 返回后 TSC::now()，无额外补偿

两条路径各自在其语义内的最早可用时刻打点。Socket 的 kernel_rx_delay 补偿将起点推到 kernel softirq 时刻。DPDK 的 burst TSC 已是 DPDK 路径最接近网卡的点。

### 数据验证
- Socket RX p50: 3,732 ns (含 kernel_rx_delay 补偿)
- DPDK RX p50: 772 ns
- 差值 ~2,960 ns ≈ kernel 协议栈开销 (中断 + softirq + TCP + socket buffer)

### 结论
1. ENA 网卡不支持 PTP 硬件时间戳，无法在网卡处打点
2. 当前设计是各路径的正确测量方式
3. DPDK 确实比 kernel 更快拿到包（~3μs 差异来自绕过 kernel 协议栈）
4. Future work: 在 PTP 网卡上可添加 rte_mbuf.timestamp 补偿

## 第 1 轮

**【激进创新者 R8 | 泛型消息 + Policy 模式】**
论点：彻底抛弃 Probe concept。时间戳是消息的编译期属性：
```cpp
struct NoTimestamp { static constexpr bool enabled = false; };
struct WithTimestamp { static constexpr bool enabled = true; uint64_t tsc = 0; };

template <size_t MaxPayload, typename TsPolicy = NoTimestamp>
struct TxMessage {
    uint8_t data[MaxPayload]{};
    uint16_t len = 0;
    uint8_t opcode = ws::opcode::kBinary;
    [[no_unique_address]] TsPolicy ts{};
};
```
`[[no_unique_address]]` 让 NoTimestamp 零开销。RX 侧同理。

**【性能狂热者 R3 | 二进制布局确认】**
论点：TxMessage<512> = 515 bytes → 576 bytes (padding)。加 8 bytes = 523 → 仍 576。RxMessage 同理。TX/RX 均零 cache line 增长。

**【架构师 R14 | RX arrival_tsc 注入点】**
论点：TX 路径清晰（enqueue 时写 msg.ts.tsc）。RX 路径：arrival_tsc 在 poll_rx 后捕获，到 deliver_message/rx_enqueue 之间穿越 TLS/WS 处理链。建议 Transport 成员变量 `current_arrival_tsc_`（RX 单线程无竞争）。

**【实用主义者 R4 | 落地问题】**
论点：三个问题：(1) Probe 回调还需要吗？(2) flush_tsc 在哪？(3) RX 用户怎么拿 arrival_tsc？

## 第 2 轮

**【R8】** 回应 R4：(1) Probe 变 Reporter，在消息"出口"报告而非管道中间 hook。签名 on_tx(enqueue, flush, opcode) / on_rx(arrival, deliver, opcode)。(2) flush_tsc 是 TX 线程局部 TSC::now()，不写回消息。(3) Pull 模式 RxMessage 自带 arrival_tsc；Push 模式通过 reporter 上报。

**【R3】** per-message flush_tsc 精度分析：TLS coalesced send 下，第一条消息的 flush_tsc 早于实际发送。偏差 = 后续编码时间 ≈ 几百 ns，可忽略。

**【R14】** 统一设计：TsPolicy 控制消息结构，Reporter 控制报告逻辑。Transport 成员 current_arrival_tsc_ 做 RX 桥接。

**【R4】** 方案可行。列出 6 步改动清单。

## 第 3 轮

**【R8】** 简化：TsPolicy 由 Reporter 自动推导。NullReporter → NoTimestamp，非空 Reporter → WithTimestamp。一个模板参数控制一切。

**【R14】** 接受合一，保留未来解耦能力。

**【R3】** 确认零开销路径干净。

**【R4】** 与 plan 方案对比：新方案 RX 零签名变更，"无感知"维度更好。

## 第 4 轮：收敛

全员共识。R8 维持泛型消息方案。R3 确认零开销。R14 接受合一和成员变量。R4 确认可行。

## 最终方案

### 核心决策
消息结构通过泛型 TsPolicy 编译期决定是否携带 TSC。TsPolicy 由 Reporter 模板参数自动推导。一个模板参数控制一切。

### 方案细节
- TxMessage/RxMessage 加 `[[no_unique_address]] TsPolicy ts{}`
- `TsPolicy = conditional_t<same_as<Reporter, NullReporter>, NoTimestamp, WithTimestamp>`
- TX：enqueue 写 msg.ts.tsc，TX loop per-message 调 reporter.on_tx(enqueue_tsc, flush_tsc, opcode)
- RX：rx_loop 写 current_arrival_tsc_，deliver_message 调 reporter.on_rx(arrival_tsc, deliver_tsc, opcode)，rx_enqueue 写 msg.ts.tsc
- NullReporter → 全路径 if constexpr 消除 → 零开销

### 已解决的分歧
- TsPolicy 与 Reporter 合一（YAGNI）
- RX arrival_tsc 用成员变量（单线程，零签名变更）
- per-message flush_tsc（偏差可忽略）

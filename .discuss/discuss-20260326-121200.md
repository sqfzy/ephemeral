## 内容摘要

用户指出优化 4（EvictingQueue 跳过中间帧入队）在多 symbol combined stream 场景下会丢失低频 symbol 的更新。分析确认这是一个 bug：一个 TLS record 中帧序列可能是 [BTC, ETH, SOL, BTC, ETH, BTC]，`last_data_frame` 只保留最后一帧 BTC，SOL 和 ETH 的更新被丢弃。根本原因是错误地将 `kRxEvicting`（队列实现细节）等同于 `kLastOnlyDeliver`（业务语义）。已完全回滚优化 4。

---

## 问题分析

优化 4 的改动：
```cpp
// 改前：每帧都 deliver
deliver_data_frame(*frame);

// 改后：EvictingQueue 只 deliver 最后一帧
if constexpr (kLastOnlyDeliver || kRxEvicting) {
    last_data_frame = &*frame;  // 只记住最后一帧
} else {
    deliver_data_frame(*frame);
}
```

在 combined stream 中，一个 TLS record 包含多个 symbol 的更新。只 deliver 最后一帧会导致其他 symbol 的更新丢失。

## 核心教训

- `kRxEvicting`（队列满时覆盖）≠ `kLastOnlyDeliver`（只关心最新快照）
- 前者是基础设施选择，后者是业务语义
- 性能优化不能改变数据可见性语义

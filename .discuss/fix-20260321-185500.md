# Fix Report

## 概况
- 时间：2026-03-21 18:40
- 耗时：~15 分钟
- 错误类型：运行时 panic (segfault) + 逻辑错误 (TCP handshake timeout)
- 提交：d1bbcd0

## 原始错误
```
[2026-03-21 18:34:03.655] [dpdk.tcp] [error] [tcp.hpp:228] TCP handshake timeout (5000ms)
[2026-03-21 18:34:03.655] [net.transport] [error] [transport.hpp:223] Initial connect failed: TCP factory failed: TCP handshake timeout after 5000ms
[2026-03-21 18:34:03.655] [error] Transport create failed: TCP factory failed: TCP handshake timeout after 5000ms
Segmentation fault
```

## 根因分析

### 根因 1: Segfault (use-after-free)
`ws_echo_client::main()` called `eal_cleanup()` while `Platform` was still on the stack.
When main() returned, Platform's destructor called `rte_eth_dev_stop()` and
`rte_mempool_free()` on already-freed EAL resources → segfault.

This affected ALL exit paths: both error returns and normal exit.

### 根因 2: TCP handshake timeout
SYN packets were sent with bare 20-byte TCP headers (no options). RFC-compliant TCP stacks
accept this, but middleboxes (DPI firewalls, load balancers, ISP equipment) commonly drop
bare SYNs because they resemble SYN flood or port scan traffic. The user's network (CERNET
university) likely has such filtering.

Verified: `openssl s_client` to the same server succeeds from the kernel stack (which sends
full TCP options), confirming the server is up and the issue is packet-level.

### 触发条件
- Bug 1: Any ws_echo_client run that exits (success or failure)
- Bug 2: Network path with middlebox that filters bare SYN packets

### 排除的假设
- Server down → confirmed reachable via `openssl s_client`
- Checksum error → software checksum code is correct (verified by tests)
- Wrong DPDK port → MAC address matches eth_main, confirming correct port

## 修复

### 改动摘要
| 文件 | 改动 |
|------|------|
| `net_header.hpp` | Add SYN options: MSS(1460) + SACK_PERM + WinScale. build_packet auto-adds when SYN flag set |
| `tcp.hpp` | Copy MSS from TcpConfig to PacketTemplate |
| `ws_echo_client.cpp` | Wrap DPDK resources in do-while(false) scope; all error paths use break instead of early return |
| `test_net_header.cpp` | 3 new tests for SYN option layout and constants |

### 修复逻辑
1. **SYN options**: Modified `PacketTemplate::build_packet()` to detect SYN flag and automatically
   append 12 bytes of TCP options (MSS + SACK_PERM + NOP + WinScale + NOP + NOP), making the TCP
   header 32 bytes (8 words). Checksums account for the larger header. Hot-path `fill_packet()`
   unchanged (only used for data packets).

2. **Segfault**: Wrapped all DPDK resource usage in `do { ... } while(false)` block. Error paths
   use `break` to exit the block, ensuring Platform/Transport destructors run before `eal_cleanup()`.

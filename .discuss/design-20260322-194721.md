# Design Report

## 概况
- 时间：2026-03-22 19:47:21
- 需求：将 resolve_hostname 纳入库，并为 connect() 增加 hostname 重载
- 讨论轮数：4 轮（前置 /discuss 会议）
- 参与角色：R7（用户代言人）、R1（风险卫士）、R3（性能狂热者）、R12（系统思维者）、R2（极简主义者）
- 提交：待用户确认

## 需求边界

**In scope**：
- `resolve_hostname()` 从 example 移入 connector.hpp
- `connect()` hostname 重载（从 transport_cfg.remote_host 自动解析）
- ws_echo_client.cpp 简化

**Out of scope**：
- URL 解析
- DNS 缓存
- 异步 DNS

## 关键设计决策

| 决策 | 选择 | 否决项 | 理由 |
|------|------|--------|------|
| DNS 位置 | 库 utility + hostname 重载 | 仅在 example | 每个 DPDK 用户都需要，实现相同 |
| DNS 失败处理 | 错误信息包含独占 NIC 提示 | 静默失败 | 帮助用户诊断环境依赖问题 |
| API 形式 | 两个重载（ip + hostname） | 仅 hostname | 独占 NIC 用户需要 escape hatch |
| hostname 来源 | transport_cfg.remote_host | 新增参数 | hostname 已存在于 TransportConfig，无需冗余 |

## 实现概况
- 修改文件：connector.hpp, ws_echo_client.cpp
- 新增代码：resolve_hostname() ~30 行 + hostname 重载 ~15 行
- 删除代码：example 中的 resolve_hostname ~25 行 + DNS 调用 ~5 行
- 净效果：run_dpdk 从 55 行降到 50 行，且用户无需手动 DNS

## run_dpdk 演变追踪
| 版本 | 行数 | 说明 |
|------|------|------|
| 原始 | ~130 | 手动 EAL/Platform/MAC/ARP/TCP/Transport |
| EalGuard + connect(ip) | ~55 | RAII + helper，手动 DNS |
| connect(hostname) | ~50 | DNS 也由库处理 |

## 后续建议
- 如需支持多连接共享 Platform，考虑将 Platform 从 ConnectResult 中分离
- 如需 DNS 缓存（reconnect 场景），在 Transport 层处理

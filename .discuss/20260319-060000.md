## 代码审阅发现的关键问题

| 严重级 | 文件 | 问题 |
|--------|------|------|
| CRITICAL | transport.hpp | `stats_` 非原子，TX/RX 线程并发读写 → 数据竞争 |
| CRITICAL | transport.hpp | `tls_` 被 TX/RX 线程并发访问 → SSL 对象非线程安全 |
| CRITICAL | websocket.hpp | `decode_frame()` payload length 整数溢出 → 绕过长度校验 |
| HIGH | tls_record.hpp | `const_cast<uint8_t*>(tag)` 写入 const 内存 |
| HIGH | tcp.hpp | `generate_isn()` 用 `std::random_device`，不满足 RFC 6528 |
| MEDIUM | tls_session.hpp | BIO user data 指针生命周期风险 |
| MEDIUM | http.hpp | 状态码解析对多空格脆弱 |
| MEDIUM | transport.hpp | RX reassembly_buf.erase() 是 O(n) |

## 结构化讨论

### 第 1 轮：独立审阅意见

**R1**：3 个 CRITICAL bug 必须冻结所有开发立即修复。stats_ 数据竞争、tls_ 并发 SSL、decode_frame 整数溢出。

**R3**：bug 修复可并行，Sprint 2 优化空间大——EVP→AEAD 可将 TLS encrypt 从 258ns 降到 120ns，E2E TX 从 664ns 降到 ~460ns。

**R6**：API 不一致（send 返回 int，recv 返回 bool）、recv() data 指针生命周期未文档化、extract_hot_state 使用非标准 exporter label。

**R11**：7 个新头文件零测试覆盖。缺少自动重连、WebSocket ping、分片重组、TLS key update、DNS 解析。

**R4**：按实际影响排优先级：tls_ 并发 P0，自动重连 P0，stats 竞争 P1，整数溢出 P1。

### 第 2-4 轮：tls_ 并发、测试策略、自动重连

核心决策：
- 删除 fallback 慢路径解决 tls_ 并发（R3+R4）
- TlsSession 只负责握手+key export（R6）
- 分层测试：先写不依赖 DPDK 的单元测试（R4）
- 重连时创建全新对象，不复用状态（R1）
- 重连逻辑 Sprint 2 先简化版放 Transport 内，Sprint 3 提取 ConnectionManager（R4+R6）

### 第 5-6 轮：Sprint 2 优化、代码完善

Sprint 2 优化清单：EVP→AEAD（~138ns 收益）、IP checksum 增量（~60ns）、TCP 头模板缓存（~70ns）。
代码完善：统一 API 风格、加 RAND_bytes 返回值检查、修 const_cast、预初始化 logger。

### 第 7 轮：最终立场

全员共识：P0 修 bug → P1 写测试 → P2 优化+功能补齐。

## 最终方案

### P0 — 立即修复
1. `stats_` 改 `std::atomic<uint64_t>` 或 TX/RX 独立 Stats
2. 删除 fallback 慢路径，TlsSession 只用于握手
3. `decode_frame()` 整数溢出防护
4. `const_cast` 改为栈复制 tag
5. enc_ctx_/dec_ctx_ 加单线程所有权注释

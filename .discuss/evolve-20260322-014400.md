## 项目画像

**定位**：高性能低延迟 WebSocket 网络库，基于 DPDK 内核旁路和 TLS 1.3，面向金融行情等微秒级延迟场景。

**核心能力**：
- SPSC 无锁队列（BoundedQueue + EvictingQueue）用于线程间通信
- 用户态 TCP 状态机（DPDK 数据面）
- TLS 1.3 加解密（AWS-LC AEAD，热路径零拷贝）
- WebSocket 协议（RFC 6455 帧编解码、掩码、控制帧）
- 通用 Transport 层（TCP→TLS→WS 握手 + 自动重连 + 双线程数据面）
- 性能工具（TSC 校准、HDR 直方图、大页内存、CPU 亲和性）

**架构概要**：5 个 header-only 模块，依赖链 `eph-base → eph-utils → eph-containers → eph-net → eph-dpdk`

**当前成熟度**：功能基本可用 → 接近生产就绪

**已有测试覆盖**：16 个测试文件，所有队列/协议/工具类均有单元测试

## 推进记录

### 缺口 1: BoundedQueue clear()
- 需求：提供单调用队列重置，替代手动 drain 循环
- 方案：head 追赶到 tail + 刷新影子索引
- 改动：bounded_queue.hpp, transport.hpp, test_bounded_queue.cpp
- 测试：3 个新测试（ClearResetsQueue, ClearOnEmptyQueue, ClearOnFullQueue）
- 提交：62fb396

### 缺口 2-3: Transport send_text(string_view) + try_recv()
- 需求：JSON API 便捷发送 + 非回调接收模式
- 方案：string_view 重载 + optional<vector<uint8_t>> 返回
- 改动：transport.hpp
- 测试：编译验证（Transport 无独立测试文件）
- 提交：0dc695c

### 缺口 4-6: EvictingQueue/BoundedQueueBytes/EvictingQueueBytes clear()
- 需求：所有队列类型一致的 clear() API
- 方案：EvictingQueue 主模板更新 reader 索引；Capacity=1 特化更新 last_seq_；字节变体委托内部队列
- 改动：evicting_queue.hpp, bounded_queue_bytes.hpp, evicting_queue_bytes.hpp, 3 个测试文件
- 测试：4 个新测试
- 提交：eac4827

### 缺口 7: Transport 连接状态变更回调
- 需求：用户可感知 connect/disconnect/reconnect/stop 事件用于监控
- 方案：TransportEvent 枚举 + TransportStateCallback 函数对象 + 在 create/stop/reconnect 路径调用
- 改动：transport.hpp
- 测试：编译验证
- 提交：99405a1

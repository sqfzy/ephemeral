## 核心决策

传输层已完备，应用层需要示例引导而非库内置。SBE 零拷贝解码复用 ITCH 的 constexpr 偏移 + byteswap 模式，FIX Session 层需独立设计。

## 立即可做

1. Binance WS JSON bookTicker 示例（连接、订阅、解析、延迟测量）
2. Binance WS SBE 示例（手动 schema 偏移，零拷贝解码，benchmark 对比）
3. 文档：EvictingQueue vs Binance auto-culling 语义对比

## 需要独立设计

4. FIX Session 层（Logon/Logout, Heartbeat, SeqNum, GapFill）— 40-80h 项目

## 暂缓

5. eph-sbe 模块（等用户需求验证）
6. Ed25519 API Key 签名（鉴权层，不在传输库范围）

## 关键论点

- SBE vs JSON 延迟差距：BBO ~50ns vs ~400ns-1µs（simdjson），L2 深度 20x 差距
- ITCH 模式可泛化：constexpr 偏移表 + byteswap = 1.4ns 解码，SBE 同构
- 库边界：通用协议解码 ∈ 库；交易所业务逻辑 ∉ 库
- FIX Session 复杂度：Logon/HeartBeat/TestRequest 状态机 + 序列号持久化 + GapFill 恢复
- Binance auto-culling 和 EvictingQueue 互补：服务端高负载丢弃 + 客户端最新值语义

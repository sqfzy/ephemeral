## 项目画像

**定位**：超低延迟 WebSocket over TLS 1.3 C++23 库，支持 DPDK 内核旁路和 POSIX socket 双后端
**核心能力**：
  - 零拷贝发送路径（WS 编码 → TLS 加密 → TCP 发送）
  - 无锁 SPSC 队列实现线程间通信
  - 自动重连（指数退避 + 抖动）
  - WebSocket 分片重组、ping/pong、优雅关闭
  - TSC 纳秒级时间精度、CPU 亲和性绑定
**架构概要**：eph-base → eph-utils → eph-containers → eph-net + eph-dpdk，全部 header-only
**当前成熟度**：功能基本可用，接近生产就绪
**已有测试覆盖**：17 个测试文件（含新增），283+ 测试用例

## 推进记录

### 缺口 1: send_for() UTF-8 校验
- 需求：RFC 6455 §5.6 要求 text frame 必须是合法 UTF-8
- 方案：在 send_for() 中检查 opcode == kText 时调用 is_valid_utf8()
- 改动：transport.hpp (3 行)
- 测试：由缺口 6 覆盖

### 缺口 2+5: send_text_for() / send_binary_for()
- 需求：与 send_text()/send_binary() 对称的带超时版本
- 方案：委托到 send_for()（UTF-8 校验已在 send_for 中）
- 改动：transport.hpp (+28 行，4 个新方法)
- 测试：编译验证（模板实例化）

### 缺口 3: close status code 校验
- 需求：RFC 6455 §7.4 限制合法 close code 范围
- 方案：新增 ws::is_valid_close_code() constexpr 函数 + SendError::kInvalidCloseCode
- 改动：websocket.hpp (+12 行), transport_types.hpp (+3 行), transport.hpp (+1 行)
- 测试：4 个新测试（标准码、保留码、越界码、注册/私有范围）

### 缺口 4: recv_n 优化
- 需求：recv_n 应与 send_n 对称使用 try_consume_n
- 方案：替换 while-try_consume 循环为 try_consume_n
- 改动：transport.hpp (重写 2 个 recv_n 重载)
- 测试：编译验证 + 已有 bounded_queue try_consume_n 测试

### 缺口 6: transport_types 测试
- 需求：TransportConfig::validate() 12 条规则零测试
- 方案：新增 test_transport_types.cpp
- 改动：tests/test_transport_types.cpp (新增), xmake.lua (+1 行)
- 测试：28 个新测试全部通过

### 缺口 7: extra_headers 校验
- 需求：非空 extra_headers 必须以 \r\n 结尾
- 方案：在 validate() 中添加 CRLF 终止检查
- 改动：transport_types.hpp (+7 行)
- 测试：2 个新测试

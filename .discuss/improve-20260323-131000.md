## Phase 3: Retrospective

### Key Decision: Error handling strategy for RAND_bytes
- Options: (A) Return error via std::expected, (B) Log and use fallback (time-based seed)
- Choice: A — propagate error
- Reason: Security-critical context (ephemeral ports, DNS IDs). Fallback would mask a serious system issue. Consistent with tcp.hpp pattern.

### Insight: Pattern inconsistency as bug indicator
- When one call site correctly checks a return value but siblings don't, the unchecked sites are almost certainly bugs, not design choices. The tcp.hpp:601 check for RAND_bytes was the proof pattern.

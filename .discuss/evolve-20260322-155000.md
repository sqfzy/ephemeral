## 项目画像

**定位**：高性能 C++23 header-only WebSocket over TLS 1.3 客户端库，支持 POSIX socket 和 DPDK 两种后端

**核心能力**：
- 零拷贝 SPSC 无锁队列（bounded + evicting，支持字节流）
- 完整 WebSocket (RFC 6455) 帧编解码、掩码、UTF-8 验证
- TLS 1.3 热路径 AEAD 加解密（密钥提取 + EVP_AEAD 单调用）
- 通用 Transport 模板：TX/RX 工作线程、自动重连、RTT 测量、ping/pong 心跳
- DPDK 用户态 TCP 状态机 + ARP + Platform 管理
- POSIX socket 后端（双栈 IPv4/IPv6）

**架构概要**：eph-base → eph-utils → eph-containers → eph-net / eph-dpdk

**当前成熟度**：功能基本可用

**已有测试覆盖**：18 个测试文件，460+ 测试用例

## 推进记录

### 缺口 1: ReceivedMessage close frame 支持
- 需求：修复 is_close() 死代码 + 添加 close_code()/close_reason()
- 方案：RX 线程在处理 Close 帧后将 payload 推入 RX 队列；添加 close_code()/close_reason() 解析器
- 改动：transport.hpp, test_transport_types.cpp
- 测试：9 个新测试
- 提交：26c5df9

### 缺口 2: TransportConfig::dump() 和 to_json()
- 需求：与 TransportStats 对称的诊断输出
- 方案：dump() 多行人类可读格式，to_json() 机器可读 JSON
- 改动：transport_types.hpp, test_transport_types.cpp
- 测试：4 个新测试
- 提交：8ca7cc2

### 缺口 3: SocketTransport::send() 总超时
- 需求：防止多次 EAGAIN 累积导致无限等待
- 方案：在 send 入口计算 deadline，每次 poll 取 min(剩余时间, send_timeout_ms)
- 改动：socket_transport.hpp
- 测试：19 个现有测试通过
- 提交：ee651a2

### 关键决策与教训

1. **性能优化的黄金标准**：rx_enqueue 的 produce() 改动同时改善了性能和代码一致性（与 BoundedQueue 分支对称）。这是唯一无争议的改进——好的优化让代码本身更好，即使不看性能数据。

2. **Loop-invariant code motion 优于 unsafe API**：将 ns_per_cycle 提升到循环外（成员变量 + rx_loop 入口初始化）达到与 to_ns_unchecked() 相同效果，但不扩大公共 API 表面积。结构性解法优先于接口妥协。

3. **半成品比不做更糟**：WS reassembly 的 2x 缓冲区 + 未使用 offset 变量是典型的"承诺了未实现的行为"——误导注释 + 内存浪费。审查原则：如果注释描述的行为代码没有实现，这比没有注释更有害。

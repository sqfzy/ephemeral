- 时间：2026-03-21 21:45:00

## 原始错误
```
test_tls_record: DecryptWithWrongSeqFails — segfault (exit code -1) on aarch64
正常解密路径不触发，仅在解密失败路径暴露。
测试中 out[48] 缓冲区 vs max_out_len=49 (payload_len 包含 16 字节 auth tag)。
```

## 根因分析

### 根因
`EVP_AEAD_CTX_open()` 的 `max_out_len` 参数传入了 `payload_len`，该值包含 16 字节 auth tag。
`max_out_len` 表示的是输出缓冲区容量（应为明文大小），而非输入密文大小。
当输出缓冲区恰好按明文大小分配时，`max_out_len > 缓冲区大小` 导致潜在越界写。

### 触发条件
- 输出缓冲区大小 < payload_len（即不含 tag 余量）
- 解密失败路径（wrong key/seq/tampered data）

### 排除的假设
- 无其他假设——retro 文档已明确指出根因

## 修复

### 改动摘要
| 文件 | 改动 |
|------|------|
| `eph-net/include/eph/net/tls_record.hpp:311` | `max_out_len` 从 `payload_len` 改为 `payload_len - tls_record::kAuthTagLen` |
| `tests/test_tls_record.cpp` | 新增 `DecryptFailureDoesNotOverrunTightBuffer` 回归测试 |

### 关键 Diff
```diff
-        if (!EVP_AEAD_CTX_open(&dec_ctx_, out, &plaintext_len,
-                                payload_len, // max_out_len
+        if (!EVP_AEAD_CTX_open(&dec_ctx_, out, &plaintext_len,
+                                payload_len - tls_record::kAuthTagLen, // max_out_len: plaintext capacity (excludes tag)
```

### 修复逻辑
AEAD 解密的输入 (in_len) 包含 ciphertext + tag，但输出只有 plaintext（= in_len - tag_len）。
max_out_len 必须反映输出缓冲区的实际容量，不能包含 tag 的 16 字节。

## 项目画像

**定位**：高性能 header-only C++23 WebSocket 客户端库，基于 DPDK 用户态网络栈，面向低延迟交易/数据流场景。

**核心能力**：
- 无锁 SPSC 队列（BoundedQueue + EvictingQueue）及字节流变体
- 完整 TLS 1.3 握手 + AEAD 热路径加解密（绕过 SSL_write/SSL_read）
- WebSocket 帧编解码（RFC 6455）
- Transport 编排层：TCP→TLS→WS Upgrade→独立 TX/RX 线程→自动重连
- DPDK 用户态 TCP 状态机 + ARP

**架构概要**：eph-base → eph-utils → eph-containers → eph-net → eph-dpdk 分层，header-only，模板单态化零开销。

**当前成熟度**：功能基本可用，接近生产就绪

**已有测试覆盖**：containers/utils/websocket/http/tls_record/tcp_concept/dpdk 均有单元测试（137+ tests all passing）

## 推进记录

### 缺口 1: TX opcode bug
- 需求：send_text() 发出的帧必须使用 kText opcode
- 方案：TX loop 按 opcode 分支 — binary 走 FrameTemplate 快速路径，其余走 encode_frame
- 改动：eph-net/include/eph/net/transport.hpp (tx_loop)
- 提交：0cde8ed

### 缺口 2: WS Close 握手响应
- 需求：收到 server Close 帧后，在 running_=false 之前发送 Close 回复
- 方案：新增 handle_close() 方法，通过 TX queue 排队 Close 帧（与 pong 同模式），TX loop 已覆盖非 binary opcode
- 改动：eph-net/include/eph/net/transport.hpp (process_ws_data + handle_close)
- 提交：0cde8ed

### 缺口 3: 超大帧日志
- 需求：超过 MaxPayload 的帧被丢弃时记录日志和统计
- 方案：在 data frame 处理前添加 payload_len > MaxPayload 检查，WARN 日志+rx_stats_.dropped
- 改动：eph-net/include/eph/net/transport.hpp (process_ws_data)
- 提交：0cde8ed

### 缺口 4: 连接状态查询 API
- 需求：应用层能查询当前连接是 connected/reconnecting/stopped
- 方案：新增 TransportState 枚举 + state() 方法，基于 running_/reconnecting_ 原子变量
- 改动：eph-net/include/eph/net/transport.hpp
- 提交：0cde8ed

### 缺口 5: 批量发送 API
- 需求：高吞吐场景一次提交多条消息，减少原子操作开销
- 方案：send_n() 接受 span 数组 + count，构建 TxMsg 数组后调用 BoundedQueue::try_push_n 单次 atomic store
- 改动：eph-net/include/eph/net/transport.hpp
- 提交：0cde8ed

### 缺口 6: WS 分片重组
- 需求：支持接收跨多帧的 WebSocket 消息（RFC 6455 §5.4）
- 方案：Transport 新增 ws_frag_buf_ + ws_frag_opcode_，process_ws_data 中区分首帧/续帧/终帧，累积到 frag_buf 直到 FIN=1 后投递；单帧消息走快速路径
- 改动：eph-net/include/eph/net/transport.hpp (process_ws_data + deliver_data_frame)
- 提交：0cde8ed

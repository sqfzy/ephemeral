## 项目画像

**定位**：C++23 header-only 超低延迟网络库，为金融市场数据/交易场景提供统一的 WebSocket + TLS 1.3 传输层，可插拔 POSIX socket 和 DPDK 用户态 TCP 后端。

**核心能力**：
- 统一 Transport API，零虚函数开销（C++20 concepts）
- WebSocket (RFC 6455) + TLS 1.3 (aws-lc) 全栈协议
- Lock-free SPSC 队列（TX/RX 线程通信）
- DPDK 用户态 TCP（内核旁路）
- ITCH 5.0 / FIX 协议解析与构建
- TSC 纳秒级计时 + HDR Histogram

**架构概要**：`eph-utils` → `eph-containers` → `eph-net`/`eph-dpdk` → `eph-itch`/`eph-fix`

**当前成熟度**：功能基本可用，接近生产就绪

**已有测试覆盖**：26 个测试目标，1221 个测试用例，覆盖所有核心模块

## 推进记录

### 缺口 1: SSL_CTX_set_default_verify_paths 返回值检查
- 需求：TLS 上下文创建时，默认 CA 路径加载失败应被检测并记录
- 方案：检查返回值，失败时 WARN 级别日志
- 改动：`eph-net/include/eph/net/tls_session.hpp`
- 测试：现有 TLS 测试继续通过（36 tests）
- 提交：db92ed6

### 缺口 2: ARP parse_arp_reply hw/proto 地址长度校验
- 需求：RFC 826 要求校验 hw_addr_len=6 和 proto_addr_len=4
- 方案：在 opcode 校验前增加两个字段校验
- 改动：`eph-dpdk/include/eph/dpdk/arp.hpp`
- 测试：现有 ARP 测试继续通过（11 tests）
- 提交：db92ed6

### 缺口 3: build_arp_request mbuf 分配失败日志
- 需求：mbuf 分配失败时应记录 ERROR 日志以便生产环境排查
- 方案：在 rte_pktmbuf_alloc 和 rte_pktmbuf_append 失败路径添加 ERROR 日志
- 改动：`eph-dpdk/include/eph/dpdk/arp.hpp`
- 测试：现有 ARP 测试继续通过（11 tests）
- 提交：db92ed6

### 缺口 4: parse_ipv4 现代化
- 需求：消除 C sscanf 依赖，使用纯 C++ 手动解析
- 方案：逐八位组解析，支持 null 指针检查和尾随字符检测
- 改动：`eph-dpdk/include/eph/dpdk/net_header.hpp`
- 测试：现有 net_header 测试继续通过（28 tests）
- 提交：db92ed6

### 缺口 5: ITCH parse_all 重复日志
- 需求：parse_all(stats) 与 parse() 对同一错误重复日志（WARN + DEBUG）
- 方案：移除 parse_all stats 版本中的重复 DEBUG 日志，保留 stats 记录
- 改动：`eph-itch/include/eph/itch/parser.hpp`
- 测试：现有 ITCH 测试继续通过（87 tests）
- 提交：db92ed6

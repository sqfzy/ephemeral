# Design Report: Mock Binance Server

## 概况
- 时间：2026-03-26 16:02:29
- 耗时：约 15 分钟
- 需求：Mock Binance WebSocket server 用于 benchmark p99 延迟测试
- 讨论轮数：2 轮（设计简单，快速收敛）
- 提交：`908106e`

## 需求边界

**In scope**：
- TLS 1.3 WebSocket server，生成 Binance combined bookTicker JSON
- `--batch-size N` 控制每 TLS record 的 WS 帧数（核心控制变量）
- `--rate N` 控速，`--duration` 限时
- 自签证书，零配置启动

**Out of scope**：
- CI 集成（后续）
- DPDK server 端
- 完整 Binance API

## 关键设计决策

| 决策 | 选择 | 否决项 | 理由 |
|------|------|--------|------|
| 语言 | Python | C++ | 测试工具，核心逻辑 30 行 vs 300+ |
| TLS record 控制 | 拼接 buffer + 单次 send | N/A | buffer < 16KB 时 OpenSSL 保证单 record |
| WS GUID | 项目自定义 GUID | RFC 6455 标准 GUID | 项目 http.hpp 用非标准 GUID，mock 必须匹配 |
| 网络 | kernel NIC loopback | 跨 NIC 互通 | AWS 不支持同机 DPDK↔kernel ENI 路由 |

## 验证结果

Batch-size sweep（kernel benchmark, 3000 msg/s, 15s）：

| batch-size | p99 | p99.9 | 说明 |
|-----------|------|-------|------|
| 1 | 4.6μs | 6.2μs | 无 batch 压力 |
| 10 | 6.6μs | 7.7μs | 轻度 batch |
| 30 | 10.3μs | 11.7μs | 模拟高流量 |
| 50 | 15.1μs | 15.1μs | 极端 batch |

p99 与 batch-size 线性相关，mock server 行为正确。

## 发现的问题

1. **项目 WS GUID 非标准**：`http.hpp:259` 使用 `258EAFA5-E914-47DA-95CA-C5AB0DC85B11`，而非 RFC 6455 的 `258EAFA5-E914-47DA-95CA-5AB5FC6D97BA`。与真实 Binance server 连接正常可能是因为不校验 accept。需要确认是否为 bug。

2. **同机 DPDK↔kernel 不通**：AWS VPC 不支持 vfio-pci 绑定的 ENI 与 kernel ENI 之间的 hairpin 路由。DPDK benchmark 无法连接同机 mock server。解决方案：用 kernel benchmark 验证，或使用第二台 EC2。

## 后续建议
- 用 mock server 验证高 batch-size 下的 decode 优化效果
- 确认 http.hpp 的 WS GUID 是否为 bug（可能影响与非 Binance server 的兼容性）
- 考虑在第二台 EC2 上运行 mock server 以支持 DPDK 测试

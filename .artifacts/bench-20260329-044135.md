## 分析

### Ping/Pong
- **RTT 中位数差异不大**（457 vs 435 us）——瓶颈在网络传输，DPDK 无法加速线路延迟
- **尾部延迟 DPDK 完胜**：p99 快 2.4x，p99.9/max 快 117x——kernel 在高负载下有严重的调度抖动（55ms 尖刺）
- **TX Queue DPDK 快 6–16x**：绕过 kernel syscall 开销显著
- **Handshake 差异极大**（1095ms vs 50ms）：kernel 的 TLS 握手 933ms 异常高，可能受 TCP Nagle/delayed ACK 影响

### Market Multi
- **RX Pipeline DPDK 快 6x**（p50: 2.6us → 0.4us）：零拷贝 + 轮询模式绕过中断和 context switch
- **Feed Latency 中位数几乎相同**（~650us）——受 mock server 发送间隔控制
- **Feed Latency max 差异巨大**（467ms vs 17ms）：kernel 侧有严重的接收延迟尖刺，DPDK 的轮询模式彻底消除

## 后续建议
- kernel TLS 握手 933ms 异常，建议排查是否受 TCP_NODELAY 或系统 TLS 库影响
- 若需稳定尾部延迟，DPDK 在 p99+ 区间有压倒性优势
- 建议以此为基线定期监控（`/bench compare`）

## Phase 2: Iteration 1

### Changes Made

1. **websocket.hpp**: Replaced `assert(payload || payload_len == 0)` with defensive `if (!payload) payload_len = 0` in both `build_ping_frame` and `build_pong_frame`. This prevents UB when called with null + non-zero length in release builds.

2. **reconnect_policy.hpp**: Added `max_backoff_` member that resolves "0 = 16x base" at construction time. Changed `std::min(current_backoff_ * 2, config_.max_reconnect_backoff)` to use the resolved value. Without this fix, exponential backoff collapsed to 0ms after the first failure.

3. **transport_types.hpp**: Centralized `kEnableTimestamps` definition (macro + `inline constexpr`) into this single header. Removed 4 duplicate definitions from transport.hpp, direct_transport.hpp, frame_processor.hpp, rx_worker.hpp, and the now-redundant `EPH_NET_ENABLE_TIMESTAMPS_DEFINED` guard pattern.

4. **transport.hpp**: Added `[[nodiscard]]` to `send_binary(string_view)`.

5. **test_reconnect_policy.cpp**: Added `DefaultMaxBackoffIs16xBase` test that verifies backoff does not collapse to 0ms when max_backoff is default (0).

## Phase 3: Retrospective

### Key Decisions
1. Chose defensive null-pointer clamping over assertion-only because release builds strip asserts, making this a silent UB on misuse paths.
2. Pre-computed max_backoff in constructor rather than checking on every attempt -- follows the project's compile-time/construction-time optimization pattern.
3. Centralized kEnableTimestamps into transport_types.hpp because all 4 duplicate sites already include it transitively.

### Lessons
- Fragile preprocessor guard patterns (#ifndef ... #define ... inline constexpr) are a code smell in C++23 -- prefer a single definition in a common header.
- Default values of 0 that mean "auto-calculate" need to be resolved at construction time, not deferred to the hot path where "0 means 0" is the natural interpretation.

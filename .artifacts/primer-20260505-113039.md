## TL;DR

`eph-net-dpdk` 是 `eph` HFT 网络库的 **DPDK 后端**：一套 header-only C++23 类，把 DPDK kernel-bypass I/O 包装成上层模块期待的 `Stream<C>` / `Datagram<C>` / `Poller` 概念。它和 `eph-net-kernel`（epoll 后端）是 **平级 sibling**，应用按需 link 一个或两个。

2026-05-02 的"daemon-led reshape"是当前形态分水岭：原本"应用进程自己 race 当 DPDK primary"的 autojoin 模型被替换为 **`eph-nicd` 守护进程独占 NIC + 应用作为 DPDK secondary 接入**。此后 API 表面收敛、跨进程协调下沉到 hugepage registry，应用侧只见到一份精简 `PlatformConfig`。代码达到 single-tenant 生产可上线水平；多 secondary 多租户场景的 4 个 RSS 集成测试目前 SKIP（S5 fixture 待复活）。

读完本 primer 你应能：(a) 看懂热路径数据流；(b) 知道五个核心抽象的契约；(c) 知道想加新 codec / 新协议 / 新 stream 类型从哪改起；(d) 避开几个有"血泪记录"的陷阱（PCAP 被 SIGSEGV、orphan mock 卡 4h、FlowDirector 握手 race）。

## 项目定位

- **是什么**：HFT 超低延迟生产环境的 DPDK 网络后端，把"DPDK 的 mempool / mbuf / poll-mode driver / 多进程"封装成上层模块（`eph-codec`、`eph-fix`、`eph-itch`、`eph-json`）能直接套用的 `Stream<Codec>` / `Datagram<Codec>` 概念实例。
- **解决什么问题**：让一个写好的 codec / 应用同时跑 kernel epoll 和 DPDK kernel-bypass 不需要双份代码；同时把 DPDK 多进程 / TLS 解密零拷贝 / RSS 多队列 / FlowDirector 这些**上层不该感知**的复杂度封进 backend。
- **为谁而做**：HFT 行情接入 / 订单路由的工程师，已熟悉 DPDK 概念，希望以 C++ concept-driven 而非 vtable 抽象在 hot path 上跑。

## 关键抽象与契约

5 个核心抽象，依次给契约 + 一个 snippet。

### 1. `eph::net::Stream<T>` / `eph::net::Datagram<T>` （concept）

定义在 `eph-net`（外部模块），eph-net-dpdk 实现它。骨架（合并 README + summary 说明）：

```cpp
// 概念示意（实际定义在 eph-net 中）
template <class T>
concept Stream = requires(T& s, std::span<const uint8_t> buf) {
    { s.send(buf) }              -> /* expected<size_t, ErrorInfo> */;
    { s.is_attached() }          -> std::convertible_to<bool>;
    { s.state() }                -> /* TcpState */;
    typename T::CodecType;
    typename T::PacketView;
    typename T::OnMessage;
};
```

实现：`DpdkTcpStream<C, EnableTls>` (`include/eph/net/dpdk/tcp_stream.hpp:43-67` 类声明）—— 依赖注入式 codec C；`EnableTls=true` 是默认。

### 2. `eph::net::Poller<T>`（concept）

定义在 `eph-net`，是 I/O 驱动核心：

```cpp
// poller.hpp:107-136 typed wrapper 简化形式
template <class P = void>  // void = 异质 type-erased 模式
class DpdkPoller {
public:
    static std::expected<std::unique_ptr<DpdkPoller>, core::ErrorInfo>
    create(PollerConfig cfg = {}) noexcept;

    template <DpdkPollable T>
    std::expected<void, core::ErrorInfo> add(T* obj) noexcept;
    template <DpdkPollable T>
    std::expected<void, core::ErrorInfo> remove(T* obj) noexcept;

    size_t poll() noexcept;                       // 非阻塞 burst
    void   set_icmp_callback(IcmpFragNeededCallback cb) noexcept;
    std::expected<uint16_t, core::ErrorInfo>
    pick_src_port(uint32_t src_ip, uint32_t dst_ip, uint16_t dst_port,
                  uint16_t range_begin = 32768, uint16_t range_end = 60999,
                  uint16_t preferred = 0) const noexcept;
};
static_assert(eph::net::Poller<DpdkPoller<>>);
```

**契约**：`poll()` 永不阻塞（DPDK busy-poll 语义），调用者拥有 lcore，pin 由调用者负责。`add/remove` 接受任意满足 `DpdkPollable` 的类型，函数指针类型擦除（**不是 std::function 不是 vtable**），在 hot path 编译为单条 indirect call。

### 3. `eph::net::dpdk::DpdkPollable<T>`（内部 concept）

```cpp
// poller.hpp 概念示意
template <class P>
concept DpdkPollable = requires(P& p, rte_mbuf** mbs, uint16_t n, uint64_t tsc) {
    { p.process_burst_(mbs, n, tsc) }  noexcept;
    { p.notify_attached_(/*DpdkPoller*/) } noexcept;
    { p.notify_detached_() }           noexcept;
    { p.tuple_for_poller_(/*...*/) }   noexcept;
    { p.on_poll_tick_(tsc) }           noexcept;
};
```

`DpdkTcpStream` / `DpdkUdpSocket` 都满足。`on_poll_tick_(tsc)` 给 TCP keepalive 用；UDP 实现为 noop。

### 4. PacketView contract → `MbufView`

`detail/mbuf_view.hpp`（90 行，全文核心）：把 `rte_mbuf*` 包装成上层 codec 期待的 PacketView 视图，关键 API：

```cpp
struct MbufView {
    const uint8_t* data() const noexcept;
    uint8_t*       writable_data() noexcept;        // 关键：允许就地改
    size_t         length() const noexcept;
    void           trim_front(size_t n) noexcept;
    void           trim_back(size_t n) noexcept;
    uint64_t       arrival_tsc() const noexcept;
};
```

**为什么要 writable_data()**：让 TLS AEAD 解密用 `EVP_AEAD_CTX_open(in==out=rec+5)` 在 NIC DMA 进来的同一块 mbuf 内存就地解密，codec 直接读 plaintext 不再 memcpy。这是整个后端零拷贝故事的核心。

### 5. `eph::dpdk::Platform`（NIC 生命周期 + 跨进程协调）

后端最复杂的类（3515 行），但用户视角接口很窄：

```cpp
// platform.hpp 概念示意（实际接口，post-2026-05-02 daemon-led）
class Platform {
public:
    // tenant 入口（应用层）
    static std::expected<Platform, std::string>
    create(PlatformConfig cfg);                    // attach as DPDK secondary

    // daemon-only 入口（eph-nicd 用）
    static std::expected<Platform, std::string>
    serve_nic(NicServiceConfig cfg);               // become primary

    void join() noexcept;                          // block until SIGTERM/SIGINT
    bool is_alive() const noexcept;                // daemon health
    std::pair<uint16_t, uint16_t> owned_queues() const noexcept;

    // ICMP cross-lcore feedback path
    [[nodiscard]] IcmpTargetHandle
    register_icmp_target(ConnectionTuple, std::weak_ptr<...>);

    // RSS / queue helpers
    bool rss_using_probed_key() const noexcept;    // ENA fallback 标识
    RxDispatchMode dispatch_mode() const noexcept;
    uint16_t       nb_rx_queues() const noexcept;
};
```

**契约**：
- `PlatformConfig` 是 **lean tenant config**：`pci` + `queues` + EAL 旁支（pins / lcores / extra_eal_args / program_name）。`proc_type=Secondary` 和 `file_prefix=eph_<sanitize_bdf(pci)>` 内部 derived，应用永远不设。
- `NicServiceConfig` 是 **daemon-side config**：NIC 物理状态（total_queues / rss_key / 描述符深度 / mempool 大小 / promiscuous / daemon_lcore）。tenants must not call `serve_nic`。
- 守护进程崩溃 → tenants 拿到 `Error::DaemonDisconnected`（仅在 control plane API 立即返回；`rx_burst` / `tx_burst` 内的逐次检测尚未完整接线，应用须用 `is_alive()` workaround）。

### 其他值得记一笔的小抽象

- `eph::core::MetricsSink` concept + `StreamMetric` enum（26 个 entry）+ `publish_metrics<Stream, Sink>` —— 两层 observability：hot path 每条 stream 拥 `alignas(64) std::atomic<uint64_t>` 数组，inc 一次单 `lock add`；冷路径 `publish_metrics` 把所有计数器 push 到任意 sink。
- `FlowRule`（RAII）+ `LocalFlowHandle` / `RemoteFlowHandle`：FlowDirector 规则，析构时自动 `rte_flow_destroy`；secondary 的 RemoteFlowHandle 通过 IPC 让 primary 安装 / 释放规则。
- `TlsInPlaceDecryptor`（`detail/tls_state.hpp`）：aws-lc AEAD wrapper，只保留 zero-copy 解密路径；TLS handshake 还是走 `eph::net::detail::TlsSession`。

## 数据流 & 控制流

### RX 热路径（每 lcore 每次 poll cycle）

```
   ┌──────────────────────────────────────────────────────┐
   │ DpdkPoller::poll()                                    │
   │                                                       │
   │  1. rte_eth_rx_burst(port_id, rx_queue_id, mbufs, 32) │
   │  2. tsc = TSC::now()  // 单次读，复用                   │
   │  3. for mbuf in mbufs:                                │
   │       entry = lookup_by_5tuple_(mbuf)  // FNV-1a O(1)  │
   │       if entry != nullptr:                            │
   │           entry->process_burst_fn(obj, &mbuf, 1, tsc) │
   │             ──┐  ←  函数指针，inline 单条 indirect call │
   │       else:    │                                      │
   │           maybe_dispatch_icmp_(mbuf)                  │
   │           rte_pktmbuf_free(mbuf)                      │
   │  4. for entry in entries (reverse):                   │
   │       if entry.tick_fn:                               │
   │           entry.tick_fn(obj, tsc)  // keepalive       │
   └────────────────────┬──────────────────────────────────┘
                        │
                        ▼
   ┌──────────────────────────────────────────────────────┐
   │ DpdkTcpStream::process_burst_(mbufs, n, tsc)          │
   │                                                       │
   │   for mbuf:                                           │
   │     ─ RX checksum drop（双模式：strict / 非 strict）   │
   │       非 strict： (olf & MASK) == BAD                 │
   │       注意 NONE = (BAD|GOOD)，不要用 & BAD bit 测试     │
   │     ─ parse_ip_header / parse_tcp_header              │
   │     ─ TcpSession::on_segment(seg, tsc)                │
   │         · 若 SYN-ACK: MSS clamp                       │
   │         · 若 ICMP feedback: effective_mss 缩小        │
   │         · 若 OOO: 进 ReorderSlots[64]，超容量 → reset  │
   │     ─ if TLS established:                             │
   │         TlsState::process_records_in_place(rec, ...)  │
   │           EVP_AEAD_CTX_open(in==out)  ← zero copy     │
   │           filter inner_ct == 0x17 (appdata)           │
   │     ─ Codec::decode(MbufView{rec, plaintext_len})     │
   │     ─ on_message(span<const uint8_t>)                 │
   └──────────────────────────────────────────────────────┘
```

**热路径不变量**：零分配、零虚函数、最多 1-2 次分支预测失误（lookup miss / checksum bad）。`[[unlikely]]` 标记的所有都是 cold case。

```
   │    （greedy first-fit + generation 防 ABA）         │
   │    ↓                                               │
   │  应用层：                                           │
   │    DpdkPoller::create({port_id, rx_queue_id})      │
   │    DpdkTcpStream::create_and_attach(cfg, platform) │
   │       └─ install rte_flow rule（FlowDirector mode） │
   │       └─ register_icmp_target → IcmpDirectory entry │
   └────────────────────────────────────────────────────┘
```

**租户崩溃 ≠ NIC 拆除**：tenant 异常退出后 daemon 仍在；`MpRegistry` 通过 `kill(pid,0)` 探活把 stale slot CAS 抢占；queue 通过 `release()` 归还（fire-and-forget，generation 防 ABA stale release）。

### ICMP 跨 lcore feedback（Type 3 Code 4 PMTU）

```
   ICMP Type 3 Code 4 由路由器发出，进 NIC 后被 RSS 哈希到 *任意* RX queue。
   它和 TcpSession 所在 queue 通常不一致 ⇒ 必须在不同 lcore 间转发。

   Lcore X (RX queue X)                 Lcore Y (RX queue Y, 拥有 stream)
       │                                    │
       │  process_burst_ 看到 ICMP，         │
       │  tuple 不在自己 entries[]           │
       │       ↓                             │
       │  maybe_dispatch_icmp_(mbuf)        │
       │    ├─ parse_icmp 提取 embedded     │
       │    │  4-tuple + next_hop_mtu       │
       │    └─ icmp_callback_(parsed)       │  ← Platform 注入的闭包
       │         ↓                           │
       │       IcmpRegistry::lookup(t)       │  shared_ptr+mutex
       │         ↓                           │
       │       handle = weak_ptr.lock()      │
       │         ↓                           │
       │       handle->on_icmp_frag_needed( ─┼─►  TcpSession::on_icmp_frag_needed
       │             next_hop_mtu)           │       (mtu)
       │                                    │       └─ atomic store effective_mss_
       │                                    │       └─ 后续 send 自动按新 MSS 切片
```

跨进程：`IcmpDirectory`（hugepage POD）保存全局 5-tuple → `owner_proc` 映射；非 owner 进程通过 `mp_ipc` 把 ICMP forward 给 owner。两阶段 publish（CAS 0→2，release-store 2→1）+ 每条 generation counter 防 stale。

### 从 clone 到能跑（HFT 工程师视角）

```bash
# 0. 系统依赖（Arch 例）
sudo pacman -S dpdk           # 系统 libdpdk + pkg-config（不要 vcpkg DPDK）
# aws-lc / numactl / tabulate 走自带 / 包管理；gtest+benchmark 自动 fetch

# 1. 配 + 构建（release 默认排除 tests/benchmarks/examples，因为每个 target set_default(false)）
xmake -m release

# 2. 显式构建测试 / bench
xmake build -g tests
xmake build -g benchmarks

# 3. 跑某一个 unit test
xmake run test_dpdk_poller          # name = .cpp 文件 basename
xmake run test_dpdk_tcp_stream
xmake run test_flow_steering

# 4. 跑 E2E（需 NIC_B 上 vfio-pci，否则 cleanly SKIP）
sudo ./benchmarks/latency/lat tcp --dpdk     # 一次性把 NIC_B 切到 vfio-pci
sudo tests/integration/dpdk_e2e

# 5. 启 daemon（生产 / 多 secondary 场景）
sudo cp etc/example.toml /etc/eph/0000:00:06.0.toml
sudo systemctl start eph-nicd@0000:00:06.0   # 见 docs/dpdk-daemon-deployment.md

# 6. 操作员检查
eph-nicctl peers --pci=0000:00:06.0
eph-nicctl stats --pci=0000:00:06.0

# 7. fuzzer（独立 Clang 构建，不在 xmake 图内 —— 见 fuzzers/README.md）
clang++ -std=c++23 -fsanitize=fuzzer,address,undefined ...
```

### 常见构建失败原因

- `pkg-config --modversion libdpdk` 失败 → 系统 libdpdk 没装好
- `aws-lc` symbol 与 vcpkg openssl 冲突 → 走系统 libdpdk 路径，不要 vcpkg DPDK
- 编译器 < GCC 13 / Clang 17 → 不支持 `std::expected` / `std::format`
- DPDK PMD 链接看似成功但 secondary attach 时 `No such device` → 忘了 `apply_dpdk_pmd_linkgroups()` 在 application target

### 日志级别 compile-time 过滤

通过 `xmake f -m <release|debug>` 自动配 `SPDLOG_ACTIVE_LEVEL`（release=INFO，debug=TRACE）。所有热路径必须用 `SPDLOG_TRACE/DEBUG/...` 宏，不能用运行时 `spdlog::trace(...)` API；suppressed 级别整个编译消失，零开销。

## 扩展点

### 想加新 codec

只需让你的类满足 `eph::core::StreamCodec<T>` / `DatagramCodec<T>` concept（`decode(PacketView, OutputBuffer&) -> expected<optional<Frame>, ...>`），然后：

```cpp
auto stream = en::DpdkTcpStream<MyCodec>::create_and_attach(cfg, platform).value();
```

**完全不需要改 eph-net-dpdk 的代码**。codec 通过模板参数注入，热路径单态化生成专属副本。

参考：`eph-codec/include/eph/codec/ws_codec.hpp` / `mold64_codec.hpp` 是范本。

### 想加新协议（例如 SCTP / QUIC）

需要在 `eph::net::dpdk::*` 里新增一个类，满足 `Stream<T>` 或 `Datagram<T>` 加 `DpdkPollable<T>` 两套 concept；同时增量补 `eph::dpdk::*` 下的 `xxxSession` 状态机或 `xxxSender`。参考 TCP 现成结构，按文件复制：

- `tcp.hpp`（Session 状态机）→ `sctp.hpp`
- `net/dpdk/tcp_stream.hpp`（用户面）→ `net/dpdk/sctp_stream.hpp`
- `static_assert(Stream<DpdkSctpStream<MyCodec>>);` 编译期保证契约

### 想加新 RX dispatch 模式

`flow_steering.hpp` 的 `RxDispatchMode` 是 enum：`Software` / `RssPartitioned` / `FlowDirector`。新增需要：
1. 扩 enum
2. 在 `Platform::detect_rx_dispatch_mode` 加运行时 NIC 探测分支
3. `DpdkTcpStream::create_and_attach` 的 dispatch-mode switch 加 case

### 想接其他 metrics sink

实现 `MetricsSink` concept（`push_counter / push_gauge / push_histogram / flush`），再 `publish_metrics(*stream, my_sink, tags)`。参考 `eph::utils::ConsoleSink` 或 `NullSink`。

## 已知陷阱 & 反模式（gotchas，不评价不建议）

> 注：以下都是代码 / 注释里有"血泪"标记或 commit 历史里有补丁印记的真实坑，新人首次接触时尤其留意。

### 协议 / 性能层

- **FlowDirector handshake race**（`tcp_stream.hpp:812-835`，标 `KNOWN LIMITATION`）：FlowDirector mode 下 rte_flow 规则在 TCP 三次握手 *之后* 才装，握手期间 SYN-ACK 由默认 RSS 哈希，可能落到非 target queue → silent drop → timeout。RssPartitioned 模式（src_port 反向匹配）规避了这个问题。
- **TLS RX checksum 双模式语义**（`udp_socket.hpp:731-738`，TD-6 注释）：非 strict 模式必须用 `(olf & MASK) == BAD` 而不是 `& BAD_bit`，因为 DPDK 把 NONE 编码为 `BAD|GOOD` 两位都置位，朴素位测试会把 NONE 错当 BAD。
- **UDP 是 fixed-peer**（`udp_socket.hpp:448-462`）：`UdpSender` 内部预填模板（peer MAC/IP/port），`send_to(data, different_addr)` 直接 `InvalidConfig`。设计如此，不要尝试"绕过"。
- **PacketTemplate / UdpPacketTemplate 不是 thread-safe**：`ip_id` 计数器无同步，每个 TX 线程必须 own 自己的实例。debug 模式有 `owner_tid_` 断言；release 模式无开销 = 静默 UB。
- **TcpSession 不实现重传 / 不开 Nagle / 不做 SACK**：HFT 选型，跨 LAN 用没问题；跨 WAN 必踩坑。Reorder buffer 64 slots 满 → connection reset 而非阻塞。
- **kMaxRssQueues = 64**（`platform.hpp` 顶部常量）：覆盖当前 ENA(≤32) / CX-5(≤63) / E810(≤256 但项目不会真用) 主流 NIC；跨过这个数得改源码。

### 多进程 / Daemon 层

- **必须先有 daemon 才能起 tenant**：`Platform::create({.pci="0000:00:06.0"})` 假设 `/var/run/dpdk/eph_<sanitized_bdf>/` 已存在；不存在直接 `Error::DaemonDisconnected`。dev 场景用 `eph::dpdk::dev::ensure_local_daemon` 自动 fork+exec。
- **daemon 重启会让所有 tenant 看到 `Error::DaemonDisconnected`**，但仅在 *control plane* API（`Platform::create` / `register_icmp_target` / etc）立即出现；`rx_burst` / `tx_burst` 内部的逐次检测**尚未完整接线**（`docs/dpdk-reconnect-pattern.md:9-19` 明确说明），需要 app 自己用 `Platform::is_alive()` 轮询。
- **跨 tenant src_port 协调是操作员的事**（`docs/dpdk-multiprocess.md`、`README.md:148-157`）：library 没有全局视图，启动两个 tenant 配同一 port range 会"诡异掉包"，eph-net-dpdk 不会预防也不会报错。
- **AmbientCapabilities 文档说要、unit 文件没写**（`etc/eph-nicd@.service` vs `docs/dpdk-daemon-deployment.md:109`）：当前 daemon 以 root 跑因此能力是隐式的，但若有人改 `User=` 而不补 `AmbientCapabilities=`，权能不会被继承。
- **DPDK MP teardown SIGSEGV（已修，但理解一下）**：commits `0b3a4aaa..e7d69bd5`（2026-04-30..05-02）解决了 primary `~Platform()` 在 secondary `rte_eth_rx_burst` 中 `rte_eth_dev_stop` 让 ENA io_cq 被释放、secondary 段错误的问题。修法：`MpRegistry::is_last_alive_proc()` gate。`docs/dpdk-mp-teardown-protocol.md` 有完整 GDB 复盘。

### 测试 / 工具层

- **legacy/ 目录的 ~23 个测试**（`tests/legacy/`）：pre-rename（eph-dpdk → eph-net-dpdk）时代的 detail 层测试，仍维护、仍 build；不是 dead code，但和 `tests/test_*.cpp` 公共面测试有部分重叠。删除前必须 diff 覆盖度。
- **4 个 RSS 集成测试当前 unconditional SKIP**：`test_dpdk_rss_bringup` / `test_dpdk_rss_fanout` / `test_dpdk_rss_key_correctness` / `test_dpdk_rss_platform`，注释里都标 `FIXME(daemon-reshape) S5 fixture unverified`。S5 的 QueueAllocator + IPC 已 land，但 fork-per-test fixture 还没在新路径上跑过。多 secondary 多 RSS-queue 场景目前**只有冒烟可信度**，没有集成自动化兜底。
- **mock_dispatcher 的 parent-death watchdog**（`tests/integration/mock_dispatcher.hpp:88-96`）：`PR_SET_PDEATHSIG=SIGTERM` 是因为有过一次 stuck child 占住端口 19000-19499 共 4 小时阻塞后续运行。不要把这段保护代码"清理掉"。
- **TCP echo mock per-connection thread** （`tests/integration/echo_mocks.hpp:59-74`）：单 accept-then-serve loop 在多 stream 测试里第二个 stream 不会被 echo，必须 detached worker thread。注释里有完整背景。
- **fuzzers 不在 xmake 图内**（`fuzzers/README.md`）：默认 toolchain GCC14，libFuzzer 要 Clang≥17。手工 `clang++ -fsanitize=fuzzer,...` 编。

### 操作 / 部署层

- **`eph-pci.txt` 是 daemon 存活标记**（`detail/default_nic_scan.hpp`）：daemon 起来时写，进程死了 EAL teardown 会清；`Platform::create({.pci=""})` 扫 `/var/run/dpdk/eph_*/eph-pci.txt`，单 daemon → 自动选；多 daemon → 报错列出候选；零 daemon → 错。stale 文件残留会造成"幽灵 daemon"。
- **bench `bench_rte_ring_vs_bq` 标题易误读**：是 *eph 内部 BoundedQueue* vs DPDK rte_ring，不是 DPDK vs kernel。
- **bench 大多无 NUMA pin**（`benchmarks/bench_rte_ring_vs_bq.cpp` 等）：单线程 CPU pin 有，跨 socket 的隐式漂移没控制；多 socket box 上数字偏抖。

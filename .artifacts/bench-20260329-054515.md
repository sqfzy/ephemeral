## 分析

### Ping/Pong（5000 samples — 高置信度）
- **RTT 完全由 Binance 服务端主导**：p50 ~51–52ms，kernel vs DPDK 差异 <3%——证实 DPDK 无法加速线路延迟
- **RX Pipeline DPDK 碾压 kernel 17–37x**（5.8us → 0.34us）——5000 样本下结果非常稳定
- **TX Pipeline DPDK 快 5–7x**（p50: 2.3us → 0.32us）
- 与 60s 短测对比：长测的 RTT p50 从 28ms 升至 52ms，说明 Binance 服务端响应时间有时段波动

### Market Multi（~400K samples — 高置信度）
- **RX Pipeline p50 DPDK 快 7.7x**（3.5us → 0.45us）——与短测一致，稳定
- **Feed Latency p50 完全一致**（2.4ms）——由网络传播主导

### ⚠️ DPDK Feed Latency 尾部异常
DPDK 的 Feed Latency p99/p99.9/max 显著差于 kernel：
- kernel: p99=3.5ms, p99.9=9.3ms, max=39ms
- DPDK:   p99=46.7ms, p99.9=217ms, max=305ms

这不是 DPDK 处理慢（RX Pipeline 全面更快），而可能是：
1. **DPDK TCP 栈的拥塞控制/重传**在长连接下表现不如 kernel TCP 栈成熟
2. **DPDK rx_burst 轮询间隙**在无数据时 CPU 空转，突然来一批数据时累积延迟
3. **Binance 服务器对两次连接的 IP 路由不同**（kernel 连到 176.34.x，DPDK 连到 13.158.x），网络路径差异导致

建议后续排查：让 kernel 和 DPDK 同时运行对比，或多轮交替运行消除时段差异。

## 后续建议
- 排查 DPDK Feed Latency 尾部异常——可能是 DPDK TCP 栈在长时间运行下的已知问题

- 建议交替运行 kernel/DPDK 消除 Binance 路由和时段差异

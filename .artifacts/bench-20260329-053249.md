## 分析

### Ping/Pong
- **RTT 由 Binance 服务器响应时间主导**（p50 ~28ms），kernel vs DPDK 差异 <5%——线路延迟掩盖了栈差异
- **RX Pipeline DPDK 快 22–30x**（7.6us → 0.34us）——这是 pong 帧从 NIC 到用户空间的纯处理延迟，DPDK 零拷贝 + 轮询优势显著
- **TX Pipeline DPDK 快 8–19x**——绕过 kernel syscall 路径
- **Handshake**: kernel TLS 握手 38.6ms vs DPDK 7.1ms（5.4x），kernel 多出的 ~30ms 可能是 kernel TLS 栈 + 系统调用开销

### Market Multi
- **RX Pipeline p50 DPDK 快 6.5x**（3.1us → 0.48us），但高百分位收窄到 1.4–1.7x——真实 Binance 流量突发时两者都面临 TCP 分片 / TLS record 边界处理压力
- **Feed Latency（server→app）中位数几乎相同**（~2.3–2.4ms）——由 Binance 推送间隔和网络传播主导
- **Feed Latency 尾部 DPDK 显著更好**：p99.9 从 10.2ms 降到 4.1ms（2.5x），max 从 16.2ms 降到 5.4ms（3.0x）——kernel 的中断合并和调度延迟在尾部暴露

## 后续建议
- RTT 对比中 DPDK 无优势——瓶颈在交易所响应，建议关注 TX/RX Pipeline 和 Feed Latency 尾部
- Kernel TLS 握手 38ms vs DPDK 7ms 差距在真实场景下也很显著——对重连场景有影响
- 建议定期用 `/bench compare` 监控 RX Pipeline 回归

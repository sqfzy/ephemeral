## 关键决策记录

### 第 1 轮起步的 GCC SFINAE idiom
`static_assert(!requires(T t){t.reset();})` 在 GCC 13 下是 hard error（不是 SFINAE 失败）。正确做法是包在 `detail::has_reset<T>` concept template 里。这个 idiom 在 9.1 建立，后续 sub-phase 沿用。

### Phase 5/7 openssl TU 冲突的延续
aws-lc 与 vcpkg-openssl 的 include 冲突在 Phase 7 通过 `getrandom(2)` + gcc14 wrapper flag 重排解决。Phase 9 的 HMAC / base64 / SHA-1 全部通过 aws-lc include 路径工作，无新冲突。

### ByteSink adapter 模式复用
9.5 为 WS handshake 创建的 4 套 Kernel/Dpdk × plain/TLS adapter 在 9.6 proxy 集成中被直接复用（复用 `PlainWsSink`）。这是 Tokio 风格 template helper 的实际收益。

### HTTP parser 的 "dumb builder" 决定
`build_http_request` 不自动填 Content-Length / Host。这让 round-trip byte 可预测，并且允许 9.5/9.6 的 wrappers 在上层加语义。这个决定在 9.3 建立，9.4 测试验证，9.5/9.6 依赖它。

### 9.6 fallback parser for CONNECT response
9.3 的 `parse_http_response` 拒绝 bodyless non-CL 响应（符合 RFC 7230 安全规则），但真实 proxies 发 `"200 Connection established\r\n\r\n"` 就是这种格式。9.6 没有修改 9.3 parser，而是加了一个 20 行的 fallback `try_parse_connect_response` 专门处理 CONNECT 响应。这是一个优秀的 scope 决定：保持 9.3 parser 的严格性 + 9.6 特殊化。

### 9.8 mock server deadlock
初次实现 `EchoServer` 析构时 join 阻塞在 accept 上。修复：`shutdown(fd, SHUT_RDWR)` 后再 join。这个 helper 在 9.8 内联，但模式可复用到未来类似测试。

## 每个 phase 发生了什么

### Phase 1 ✅ — Factory + ICMP 上移

**Before**: `DpdkTcpStream` 有 3 个 factory；`create(cfg, poller)` 和
`create_and_attach` 职责重叠；ICMP callback 单 poller 级，RSS 多队列下
不稳。

**After**: `create(cfg, poller)` 删除。`create_and_attach` 成为生产唯一
路径，内部：

1. 队列选择（Software / RssPartitioned / FlowDirector）
2. src_port 分配（可能 rebind 匹配 RSS hash）
3. TCP/TLS/WS 握手
4. Poller attach + FlowRule install（如适用）
5. **新**：`platform.register_icmp_target(tuple, TCP, stream, thunk)`
   返回 RAII handle

`Platform` 新增：
- `register_icmp_target(tuple, proto, stream, cb)` → `IcmpTargetHandle`
- `unregister_icmp_target_`（供 RAII handle 析构时调用）
- `on_poller_icmp_` 静态 trampoline（installed on 每个 poller via `set_icmp_callback`）
- `icmp_frag_needed_dispatched()` 诊断计数器
- 内部 `IcmpEntry` registry + `dispatch_icmp_` 精确匹配

**Impact**: RSS 多队列下每个 poller 把未匹配的 ICMP 送到 Platform 层
统一 dispatch。无论响应落到哪个队列，都能找到正确的 stream。

### Phase 2 ✅ — `on_poll_tick_` 统一

**Before**: keepalive tick 只在 `DpdkTcpStream::poll_once_` 驱动。
DpdkPoller 模式下走 `process_burst_`，不经过 `poll_once_`，keepalive 永不 tick。

**After**: `DpdkPollable` concept 新增 `on_poll_tick_(uint64_t tsc) noexcept`
要求。`DpdkPoller::poll()` 末尾扫过所有 entries 挨个调 tick，不论 burst
是否有 mbufs。

- `DpdkTcpStream::on_poll_tick_` → `sess_.tick_keepalive`
- `DpdkUdpSocket::on_poll_tick_` → inline no-op
- 测试 Pollables 也补了 no-op
- `poll_once_` 里冗余的 tick 删除（现在由 Poller 驱动）

**新 test pin** (`test_dpdk_poller`): 即使 burst=0 tick 依然触发；空 poller 不触发。

### Phase 3 ✅ — 析构 RST 白名单

**Before**: `~TcpSession` 对所有非 Closed 状态都发 RST —— 包括 FinWait1 /
Closing 等 peer 已经在有序关闭的状态。tcpdump 里看起来像 abort 打断
graceful close。

**After**: `should_rst_on_destroy_(state)` 显式 switch：
- **RST**: `Established / SynSent / SynReceived / CloseWait` (peer 认为 live)
- **Skip**: 其他一切（包括所有中间关闭态）

4 个新测试 pin 每个状态的策略 + scoped-lifetime 测试验证 FinWait1 析构路径
无 side effect。

### Phase 4 ⚠️ — TcpSession error 类型 (REVISED)

原计划：`TcpSession::connect/send/close/poll_rx/process_rx` 签名
`std::string` → `core::ErrorInfo`。

**实施中 revised**：重读 ErrorInfo 设计后发现 `detail` 是 `const char*`
static-lifetime only。TcpSession 现在的错误带有 **formatted detail**
（timeout 值、seq、effective MSS、peer state），对 ops diagnose 很有用。
全量转换会丢失所有 formatted context，且 TcpSession 是 DpdkTcpStream
的实现细节，用户从来不直接看 std::string。

**Final decision**: 保持 `std::string` 内部，在 tcp.hpp 加一段 20-行
design doc 显式声明这是有意的 layering。DpdkTcpStream 的 boundary
adapter pattern 保持不变（和 kernel backend 的 POSIX-errno adapter
同构）。

**重新思考的理由**：这次 blueprint 的关键词是"去繁就简"。强行对齐字符串
类型只为美观要改 100+ 行、丢失 debuggability、增加代码复杂度——反向。
保留 layered error + 明确文档化 = 真正的简化。

### Phase 5 ✅ — metric() bounds check

所有 4 个 backend (`KernelTcpStream` / `KernelUdpSocket` / `DpdkTcpStream` /
`DpdkUdpSocket`) 的 `metric()` accessor 前加了：
```cpp
if (static_cast<size_t>(m) >= kCount) return 0;
```

防御 enum drift / reinterpret_cast 越界。两个新 test：全范围枚举遍历
无崩溃 + 超界枚举返回 0 验证。

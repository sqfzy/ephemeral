## 🔴 Critical 问题

### C1. [DPDK] process_rx free_list 栈缓冲区越界

**文件**：`eph-dpdk/include/eph/dpdk/tcp.hpp:524`
**类型**：correctness/security
**描述**：`free_list[32]` 固定大小，但 `process_rx` 接受 `uint16_t nb_pkts`（最大 65535）。若 `nb_pkts > 32`，`free_list[free_count++]` 栈溢出。实际调用者（poll_rx、connect）传 32，但接口不阻止更大值。
**建议**：添加 `static_assert` 或 runtime clamp：`const uint16_t max_pkts = std::min(nb_pkts, uint16_t{32});`，或将 free_list 大小改为模板参数。

### C2. [net] WebSocket GUID 与 RFC 6455 不匹配

**文件**：`eph-net/include/eph/net/http.hpp:261`
**类型**：correctness/security
**描述**：`validate_ws_accept()` 使用的 GUID 是 `C5AB0DC85B11`（Binance 变体），RFC 6455 标准值是 `C5AB5DC85B11`。这导致与所有非 Binance 服务器的 WebSocket 握手验证失败。
**建议**：使用 RFC 6455 标准 GUID，或改为可配置参数（默认标准值）。

### C3. [net] TLS encrypt() 越界写入明文缓冲区

**文件**：`eph-net/include/eph/net/tls_record.hpp:267`
**类型**：correctness/security
**描述**：`encrypt()` 在 `plaintext[plaintext_len]` 处写入 TLS 1.3 内容类型字节，要求调用者预留 1 字节。缓冲区恰好等于 payload 大小时会写越界。当前调用点（transport.hpp:2020）用 `+1` 满足了此要求，但契约脆弱。
**建议**：在 encrypt 内部分配内容类型字节到输出缓冲区，或在 transport.hpp 中添加 `static_assert` 验证缓冲区大小包含 +1。

### C4. [net] DNS 解析超时导致线程和内存泄漏

**文件**：`eph-net/include/eph/net/socket_transport.hpp:363`
**类型**：correctness
**描述**：DNS 超时后 `std::async` 线程继续运行，`getaddrinfo` 成功时返回的 `addrinfo*` 永远不会 `freeaddrinfo()`。重连循环中反复 DNS 超时会无限泄漏。
**建议**：用 shared_ptr 控制清理——async 线程完成后自行 freeaddrinfo。

### C5. [containers] EvictingQueue Capacity=1 seqlock unlock 用 relaxed store

**文件**：`eph-containers/include/eph/containers/evicting_queue.hpp:680`
**类型**：correctness（memory ordering）
**描述**：Capacity=1 特化的 seqlock unlock 用 `relaxed` store + 前置 release fence，在 ARM64 上不等价于 `release` store（编译器可能将 store 重排到 fence 之前）。主模板（line 230）正确使用了 `release` store。
**建议**：将 line 680 改为 `seq_.store(seq + 2, std::memory_order_release)`。

## 🟡 Major 问题

### M1. [containers] EvictingQueueBytes push_count_ / last_pop_id_ 数据竞争
**文件**：`evicting_queue_bytes.hpp:571,576`
**描述**：plain `uint64_t` 被写线程写入、stats() 从其他线程读取，ARM64 上是 UB。
**建议**：改为 `std::atomic<uint64_t>` + relaxed ops。

### M2. [containers] EvictingQueue last_global_index_ / last_seq_ 数据竞争
**文件**：`evicting_queue.hpp:163,642`
**描述**：与 M1 相同模式——plain 变量被监控函数跨线程读取。
**建议**：改为 atomic + relaxed ops，或限制 stats() 只能从写线程调用。

### M3. [utils] cpu.hpp CPU_SET 缺少 cpu_id >= CPU_SETSIZE 检查
**文件**：`eph-utils/include/eph/utils/cpu.hpp:244`
**描述**：`cpu_id >= 1024` 时 CPU_SET 写越界（UB）。
**建议**：添加 `if (cpu_id >= CPU_SETSIZE)` 检查。

### M4. [utils] hdr_histogram.hpp get_mean() 中 uint64_t 乘法溢出
**文件**：`eph-utils/include/eph/utils/hdr_histogram.hpp:462`
**描述**：`sum += mid * count` 大数相乘可能溢出 uint64_t。
**建议**：用 double 累加。

### M5. [utils] hugepage.hpp munmap 大小不匹配
**文件**：`eph-utils/include/eph/utils/hugepage.hpp:140`
**描述**：hugepage 分配后 `munmap` 用非 hugepage-aligned 大小，某些内核上是 UB。
**建议**：hugepage 时 round up `out_allocated_size` 到 2MB。

### M6. [utils] system_stats.hpp 无条件包含 POSIX 头文件
**文件**：`eph-utils/include/eph/utils/system_stats.hpp:9`
**描述**：`#include <sys/resource.h>` 在 Windows 上不存在。
**建议**：`#ifdef __linux__` 保护。

### M7. [utils] recorder.hpp 多 ConcurrentRecorder 共享单个 thread_local slot
**文件**：`eph-utils/include/eph/utils/recorder.hpp:1010`
**描述**：同一线程交替使用两个 ConcurrentRecorder 导致反复 retire+recreate，数据碎片化。
**建议**：用 `thread_local map<SharedState*, Guard>` 为每个 recorder 独立存储。

### M8. [net] reconnect 期间 TX 线程可能解引用 null crypto_
**文件**：`eph-net/include/eph/net/transport.hpp:2049,2643`
**描述**：TX 线程读 crypto_ 时 RX 线程可能正在 reset() 它。虽有 reconnecting_ 标志保护，但存在竞争窗口。
**建议**：解引用前 null-check crypto_。

### M9. [net] close_gracefully() 和 stop() 对 pending_close_reason_ 数据竞争
**文件**：`eph-net/include/eph/net/transport.hpp:893`
**描述**：app 线程写 `std::string`，其他线程可能同时读。
**建议**：用 atomic flag 保护。

### M10. [dpdk] reset() 不清空 reorder buffer
**文件**：`eph-dpdk/include/eph/dpdk/tcp.hpp:803`
**描述**：reset 后 reorder_count_ 非零，新连接可能交付上一个连接的残留数据。
**建议**：reset() 中加 `reorder_count_ = 0; ack_pending_ = false;`。

### M11. [dpdk] TcpSession 默认 move 构造器留下源对象可用
**文件**：`eph-dpdk/include/eph/dpdk/tcp.hpp:310`
**描述**：moved-from 对象保留 pool_ 和 shared_rx_ring_ 指针，可能导致 double-use。
**建议**：自定义 move ctor，将源对象指针置空、state_ 置 Closed。

### M12. [fix] FIX session cfg_.heartbeat_interval_sec 数据竞争
**文件**：`eph-fix/include/eph/fix/session.hpp:311`
**描述**：RX 线程写、timer 线程读，非 atomic。
**建议**：改为 `std::atomic<int>`。

### M13. [fix] SequenceReset-GapFill 允许反向重置序列号
**文件**：`eph-fix/include/eph/fix/session.hpp:357`
**描述**：恶意/错误的对端可发 NewSeqNo=1 重置期望序列号，允许重放攻击。
**建议**：GapFill 模式下拒绝 `ns <= expected_inbound_seq_`。

### M14. [fix] on_rx 解析失败返回 false，与"应用消息"不可区分
**文件**：`eph-fix/include/eph/fix/session.hpp:252`
**描述**：parse() 失败时返回 false（"非 session 消息"），应用层会尝试处理垃圾数据。
**建议**：返回 true（session 已处理）或用三态返回值。

### M15. [fix] set_price 对 INT64_MIN 签名整数溢出（UB）
**文件**：`eph-fix/include/eph/fix/builder.hpp:305`
**描述**：`-mantissa` 当 `mantissa == INT64_MIN` 是 UB。
**建议**：`uint64_t abs_val = -static_cast<uint64_t>(mantissa)`。

### M16. [containers] EvictingQueueBytesStats::throughput() 语义错误
**文件**：`eph-containers/include/eph/containers/evicting_queue_bytes.hpp:65`
**描述**：用 `last_pop_id` delta 计算吞吐量，但 ID 差包含了被跳过（evicted）的消息，严重高估实际消费速率。
**建议**：添加 `total_popped` 字段并用它计算 throughput。

## 亮点

- **TLS 热路径优化**：TlsKeyMaterial 将 read-only key/IV 和 hot write seq 分离到不同缓存行，消除 false sharing。
- **密钥材料清理**：所有 TLS 析构和 move 操作一致使用 OPENSSL_cleanse()。
- **零拷贝协议解析**：FIX/ITCH 解析器返回 string_view 指向原始缓冲区，零堆分配。
- **deferred ACK 设计**：将 send_ack() 的 rte_eth_tx_burst 移出 RX 延迟关键路径。
- **Two-phase frame filter**：多 symbol 流的 per-symbol 去重是巧妙的优化。
- **ErrorEnum concept**：消除了每个枚举的 formatter 样板代码。
- **Reorder buffer + telemetry**：分层渐进设计，数据驱动决策。
